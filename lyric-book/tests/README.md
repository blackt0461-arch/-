# LYRIC BOOK のテスト（Google Apps Script のまね）

本物の受け口（Google）を使わずに、`server/Code.gs` をそのまま Node で動かして試すためのもの。

- `gas.mjs`：DriveApp・Utilities・PropertiesService などのまね
- `e2e2.mjs`：登録・録音・電波なし・かぶり・バックアップ・戻す・パスワードの作り直し
- `e2e3.mjs`：管理する人とメンバー（招待の合言葉・外す）
- `e2e4.mjs`：2.0 の機能（ジャケット・推定・本番モード・セットリスト・最近消した曲・みんなの曲）
- `e2e5.mjs`：速さ（受け口を2.5秒かかるまねにして、開く速さと録音の再生を測る）
- `e2e6.mjs`：2.2 の機能（自分のタブ・歌手の曲の一覧・リリース年・保存ボタンの位置・線）

## 動かし方
1. リポジトリの親フォルダで `python3 -m http.server 8765`（`http://localhost:8765/lyric-book/` が開けるように）
2. このフォルダで Playwright（chromium）を使えるようにして `node e2e5.mjs` など
   - 各ファイルの先頭の `createRequire(...)` と Code.gs のパスは、自分の環境に合わせて直す
   - e2e2〜e2e4 は画面写真の保存先を引数で受け取る（`node e2e4.mjs ./shots`）
- 本物の受け口の URL には lb_signup を送らないこと（データが空だと、その人が管理する人になってしまう）
- `e2e7.mjs`：2.3 の歌詞の取りこみ（J-Lyric.net に本当に1曲だけ問い合わせる）
- `e2e11.mjs`：2.3.2 の直し（歌詞を取ってきたときに自分の保存どうしがぶつかって「別の端末の版」ができない・ページを離れても歌詞が残る・本当に別の端末で直したときは今までどおり残す）。J-Lyric.net には問い合わせない（まねの返事）。`node e2e11.mjs`（受け口の遅さをミリ秒で渡せる。はじめは 2500）
- メモ：e2e2 は古い画面（#first）のままで、いまの版では最初で止まる
- `e2e12.mjs`：2.3.3 の文字の選び方（タップで1文字・横になぞって続けて・縦はスクロール・iPhone の選ぶ印が出ない）。e2e6 の線のテストも、横になぞる形に直した
- `e2e13.mjs`：2.3.4 の速さ（受け口を2.5秒かかるまねにして、保存→曲のページ・消す→前の画面の時間を測る。直す前は約2.5秒、直したあとは0.1秒ほど）
- メモ：e2e11 の引数は受け口の遅さ（ミリ秒）。ほかのテストのように画面写真のフォルダを渡すと 0 秒あつかいになる
- `e2e8.mjs`：2.4 の音域の取りこみ（KEYTUBE に本当に1曲だけ問い合わせる）
- `e2e9.mjs`：2.5 の機能（招待リンク・曲名の候補・パート自動・おすすめキー・音源から合わせる・検索から入れる・おまかせセットリスト）

## 2.6 で足したテスト
- `e2e10.mjs`：音源から合わせる（行が終わったらタップ）→ 原曲の音源を保存 → 本番モードで原曲を読みこんで進む。
- `ui.mjs`：新しい画面を、明るい／暗い × スマホ／iPad で撮る（scratchpad/ui に出る）。
- `enc.mjs`：4分の音を MP3 にしたときの大きさ・時間を見る（約1.4MB）。
- メモ（2.6.1）：e2e4 は 2.5 から（歌手を足すとすぐ曲の一覧が出るため）#photo の所で止まる。2.6.0 そのままでも同じ。e2e7・e2e8 は本物のサイトに問い合わせるので、必要なときだけ
