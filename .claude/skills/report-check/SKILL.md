# レポートチェック

利用者は理工学部 電子情報工学科の大学生。**返事はすべて日本語**、専門用語を避けて短く。
チェックの細かい基準は同じフォルダの `checklist.md` にある。**チェックを始める前に必ず読む。**
これまでのレポートで直したこと・指摘されたことは `lessons.md` にある。**チェック・作成・手直しのたびに最初に読み**、
新しく直したことがあれば `lessons.md` に追記する（個人名・学籍番号・点数・測定データは書かない）。

**レポートの作成や手直しを頼まれたとき**
- 授業の生成AIのルールを先に確かめる。提出用の本文を丸ごと書かない。全文の見本を作るときは「AIが作成した見本・提出用ではない」と表示し、氏名を入れない。
- すでに「AIの貼り付け」を指摘されている授業では、文章を作らず、道筋の説明と本人が手で書いたもののチェックにとどめる。
- 図・表・数式・グラフ・レイアウトは手伝ってよい。Word の部品は `scripts/docx_parts/`（使い方は同じフォルダの README.md）。

作業は次の順で行う。各段階の最初に「いま〇〇をしています」と1行で知らせる。

## 1. 受け取るもの(足りなければ、チェック前に聞く)

1. **レポート本体**: Word / PDF / コピペ。
2. **課題の情報(必須)**: 課題文・テーマ・文字数・形式(様式、図表の扱い、提出形式)・参考文献の指定など、
   先生から出ている情報すべて。渡されていなければ、チェックを始める前に
   「課題文や先生の指定(文字数・形式など)を、コピペかスクショで送ってください」と必ず聞く。
   本人が「ない」と答えたときだけ、課題条件のチェックを飛ばし、結果にそう書く。
3. **レポートの種類**: 次から選んでもらう。言われなければ中身から判断し、「〇〇として見ます」と最初に伝える。
   1. 授業レポート(考察・意見型)
   2. 実験・実習レポート
   3. 論文型(ゼミ論・卒論)
   4. その他(本人の説明に合わせる)
4. **直した版のファイル形式**: Word(指定なしならこれ)/ PDF / テキスト。

## 2. 読み取り

```
python3 .claude/skills/report-check/scripts/extract.py <レポートのファイル> --out レポート添削結果/<名前>
```
- 段落番号つきの本文(`paragraphs.txt`)、数式も読める本文(`report.md`、Word のとき)、
  文字数(`stats.txt`)、Word に入っている図の画像(`images/`)ができる。
- **PDF や図のあるレポートは、Read ツールでページや画像も目で見る**(グラフの軸ラベル・単位・図番号の確認のため)。
- コピペのときはテキストを `レポート添削結果/<名前>/input.txt` に保存してから同じスクリプトにかける。
- 出力先 `レポート添削結果/` は Git に保存しない(個人のレポートのため。`.gitignore` 済み)。

## 3. チェック

`checklist.md` の項目を、種類に応じてすべて見る。

- A. 誤字脱字・文法・文体(「です・ます」と「だ・である」の混在など)
- B. 構成と話の流れ
- C. 主張と根拠・論理の飛躍
- D. 引用・参考文献
- E. 課題の条件を満たしているか(文字数は `stats.txt` の数字で判断する)
- F. 事実の間違い: 怪しい数値・年号・定義・公式だけ WebSearch で確かめる。確かめられないものは「要確認」とし、断定しない。
- G. AIっぽいと思われそうな箇所(%の判定は**出さない**)
- H. 電子情報工学向けの追加チェック(実験レポート・論文型では特に重点的に)
- I. 考察の質（「いる？」「なぜ言い切れる？」、矛盾、数字の出どころ、比べ方、丸め、設問の答え漏れ）
- J. 見た目（図表の説明と番号、字下げ、数式、グラフ）

**守ること**
- 実験データ・測定値・本人の意見や結論は勝手に変えない。おかしいと思ったら「確認してください」と指摘するだけ。
- 書かれていない実験内容や引用文献を作り出さない。足りない情報は「ここに〇〇を書く」と空欄で示す。
- よい点も具体的に伝える。

## 4. 結果の出し方(この順で、チャットに書く)

1. **全体のひとこと**: よい点 1〜3 個 と、**いちばん大事な直しどころ 3 つ**。
2. **指摘の一覧**: 重要度「大・中・小」の順。1件ごとに
   - 種類(A〜H) / 場所(段落番号やページ) / 元の文の引用 / 何が問題か(ひと言) / **直した例文**
   - 同じ種類の小さなミス(誤字など)が多いときは、まとめて表にする。
3. **全部直した版**をファイルで渡す(下の手順)。最後に「どこを大きく変えたか」を 3 行以内で伝える。

## 5. ファイルを作る

指摘と直した版を JSON にまとめ、スクリプトでファイルにする。形式は `scripts/make_outputs.py` の先頭の説明を見る。

```
python3 .claude/skills/report-check/scripts/make_outputs.py レポート添削結果/<名前>/result.json --format docx
```
- `--format` は docx / pdf / txt(複数可: `--format docx pdf`)。
- 元が Word のときは、**元のファイルの書式・図・表を残したまま**段落を差し替える(段落番号で指定)。
  変更した段落に色をつけた「変更箇所つき」版も一緒にできる。
- 元が PDF・コピペのときは、直した全文(Markdown、数式は `$...$`。式番号は `\tag` が使えないので `$$ ... \qquad (1) $$` と書く)から新しく作る。
- 指摘一覧の PDF(`指摘一覧.pdf`)も必ず作る。
- できたファイルは SendUserFile で渡す(直した版・変更箇所つき版・指摘一覧)。

## 6. その後

「この指摘をもっと詳しく」「ここは直さないで」などの続きの頼みに応じて、直した版を作り直す。
