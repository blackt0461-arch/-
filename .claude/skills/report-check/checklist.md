# チェックの基準

重要度の目安
- **大**: 減点・不合格につながる(課題条件を満たしていない、結論がない、データと考察が矛盾、引用元がない盗用の疑い、事実の誤り)
- **中**: 評価が下がる(論理の飛躍、根拠不足、図表の不備、文体の混在、参考文献の書き方の乱れ)
- **小**: 読みやすさ(誤字、言い回し、句読点、表記ゆれ)

---

## A. 誤字脱字・文法・文体

- 誤字・脱字・変換ミス(「以外/意外」「保障/保証/補償」「制御/製御」「特性/特製」など)
- 「です・ます」と「だ・である」の混在。レポートは原則「だ・である」。
- 話し言葉: 「〜けど」「なので、」(文頭)「すごく」「いろんな」「〜じゃない」「やっぱり」「〜とか」
- 主語と述語のねじれ(「私の考えは、〜すべきだと考える」)
- 一文が長すぎる(目安 80 字超、「〜が、〜が」「〜し、〜し」の連続)
- 表記ゆれ(「データ/デ−タ」「出来る/できる」「1つ/一つ」、全角/半角英数字の混在、単位の書き方の不統一)
- 句読点の種類の混在(「、。」と「,.」と「，．」)。理工系は「，．」指定の先生も多い→課題指定を優先し、指定がなければ統一されているかだけ見る。
- 「〜と思う」の多用(根拠のある主張は「〜と考えられる」「〜である」)

## B. 構成と流れ

種類ごとの基本の型(課題で型の指定があればそちらを優先)

| 種類 | 期待する構成 |
|---|---|
| 授業レポート | 序論(問い・立場)→ 本論(根拠・具体例・反対意見の検討)→ 結論(問いへの答え) |
| 実験レポート | 目的 → 原理(理論) → 実験方法(装置・手順) → 結果 → 考察 → 結論 → 参考文献(+課題・設問への解答) |
| 論文型 | 要旨 → 序論(背景・先行研究・目的)→ 方法 → 結果 → 考察 → 結論 → 参考文献 |

- 必要な章が抜けていないか、順番がおかしくないか
- 序論で立てた問い・目的に、結論が答えているか(**目的と結論の対応**)
- 段落ごとに言いたいことが 1 つか。段落の最初の文で要点が分かるか
- 結果と考察が混ざっていないか(実験レポート: 結果=事実、考察=解釈)
- 同じ内容の繰り返し、本題と関係ない話

## C. 主張と根拠

- 主張に根拠(データ・文献・具体例)がついているか
- 「〜だから〜」の間がつながっているか(飛躍)
- 一般化しすぎ(「すべての」「必ず」「誰もが」)
- 因果と相関の取り違え
- 反対の考えや限界に触れているか(考察・論文型)
- 考察が「結果の言い直し」だけになっていないか → 「なぜそうなったか」「理論値とのずれの原因」「改善案」があるか

## D. 引用・参考文献

- 本文中の引用箇所と参考文献リストが対応しているか(番号の抜け・使われていない文献)
- 他人の文章・図をそのまま使っている箇所に出典があるか(なければ**大**)
- Wikipedia・個人ブログだけに頼っていないか(→ 教科書・論文・公的機関のページを勧める)
- Web ページに閲覧日があるか
- 書き方の統一。課題の指定があればそれに従う。指定がなければ統一されているかを見て、次の SIST02 風の形を提案する:
  - 本: 著者名. 書名. 版, 出版社, 出版年, ページ.
    例) 山田太郎. 電気回路の基礎. 第2版, 〇〇出版, 2020, p.45-50.
  - 論文: 著者名. 論文名. 雑誌名. 出版年, 巻(号), ページ.
  - Web: 著者名(または組織名). "ページ名". サイト名. 公開年. URL, (参照 2026-10-31).
  - 本文中は [1] [2] の番号方式。

## E. 課題の条件

課題の情報を表にして 1 つずつ ○ / × / △ をつける。
- テーマ・設問にすべて答えているか(設問が複数あるときは 1 つずつ)
- 文字数・ページ数(`stats.txt` の「空白を除く文字数」で判断。参考文献を含むかは課題文で判断、不明なら両方示す)
- 様式(表紙、学籍番号・氏名、フォント、段組、図表の扱い、ファイル形式、ファイル名)
- 締め切りや提出方法の指定は、レポートの中身では判断できないので「確認してください」と添える

## F. 事実の確認

- 怪しいものだけ確かめる: 物理定数・公式・定義・年号・人名・統計の数字・規格名
- WebSearch で確かめ、出典を添える。確かめられないものは「要確認」。
- 計算できるもの(単位換算、理論値の計算、誤差率)は自分で計算し直して確かめる(必要なら python で)。

## G. AIっぽいと思われそうな箇所

**%や「AIが書いた/書いていない」の判定はしない。** 「先生にそう見られそうな書き方」を指摘し、本人らしく直す案を出す。

見るところ
- 中身のない一般論・まとめ(「〜は非常に重要であると言える」「様々な観点から考える必要がある」「今後のさらなる発展が期待される」)
- 決まり文句の多用(「〜において」「〜という観点から」「総じて」「多角的に」)
- 具体例・自分の体験・自分の実験データへの言及がない
- 箇条書きや「第一に、第二に、第三に」ばかりで、自分の考えのつながりがない
- 段落ごとに文体・語彙の難しさが急に変わる
- 授業で扱っていない用語や、出典のない「それらしい」数字
- 実験レポートで、自分の測定値ではなく一般論だけで考察している

直す方向: 自分の測定値・授業の内容・自分が疑問に思ったことを入れる。抽象的な締めの文を削る。

## H. 電子情報工学向けの追加チェック

数値・単位
- 有効数字がそろっているか(測定器の精度より多い桁を書いていないか、計算結果の桁)
- 単位が書かれているか。SI 単位と接頭語の書き方(kΩ、μF、mA、dB、Hz。「K」と「k」、「u」と「μ」の誤り)
- 数値と単位の間の空き、量の記号は斜体・単位は立体(Word の場合は指摘のみ)
- 理論値と測定値を比べているか。誤差(誤差率 = |測定値−理論値| / 理論値 × 100%)を計算しているか、その値は正しいか
- 誤差の原因が具体的か(「測定誤差のため」だけで終わっていないか → 内部抵抗、プローブの容量、素子の公差、読み取り誤差など、実験に合った原因)

図・表
- 図表に番号と説明(キャプション)があるか。**図は下、表は上**にキャプション
- 本文で「図1に示すように」と参照しているか
- グラフの軸ラベルと単位(「周波数 f [Hz]」)、凡例、目盛り。周波数特性は片対数グラフが適切か
- 測定点はマーカー、理論値は線、など区別されているか
- 回路図: 素子の値・記号、測定点の位置が書かれているか

数式
- 式番号 (1)(2) があり、本文で参照しているか
- 記号の意味が式のすぐ後で説明されているか
- 式の変形に飛躍がないか、次元(単位)が合っているか

実験方法
- 使った装置(型番)・条件が、ほかの人が同じ実験をできる程度に書かれているか
- 過去形で、手順書の写しになっていないか(「〜せよ」「〜する」→「〜した」)

プログラム(情報系の課題)
- コードの説明があるか、長いコードは付録に回しているか
- 実行結果と考察(計算量、なぜその結果になるか)があるか

## 英語のレポート・英語の要旨(Abstract)

- 文法(冠詞 a/the、単数・複数、時制: 方法・結果は過去形、一般的事実は現在形)
- 和製英語や不自然な直訳
- 要旨が「目的・方法・結果・結論」を含み、指定語数に収まっているか
