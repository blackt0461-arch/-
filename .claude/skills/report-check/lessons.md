# これまでのレポートで学んだこと（教訓メモ）

## 0. まず守ること（学問的誠実さ）

- 授業ごとの生成AIのルールを、ガイダンスや指導書で**最初に確認**する。
  - 例：電子情報工学実験IIは「生成AIは文章の校正・改稿まで（レベル3）。出力をそのまま写すのは不可。コピペ・剽窃は懲戒（写させた側も）」。
- 提出用の本文をAIが丸ごと書かない。どうしても全文を作るときは、冒頭に**「AIが作成した見本・提出用ではない」**と赤字で入れ、**氏名・学籍番号は入れない**。
- すでに「AIの貼り付け」を指摘されている授業では、文章を作らない。道筋の説明と、本人が手で書いたもののチェックに切り替える。
- **データを作らない**。読み取っていない数値は空欄にして「読み取っていない」と書く。
- 友達のレポートと比べるときは、違いを示すだけにする。友達の文・図・データは取り込まない。言い回しが近い文は書き換える。
- 本人しか知らない事実（使った器具、測り方、抵抗の許容差、写真）は**本人に聞く**。「書いていないところは指導書の手順どおり」と言われたら、指導書の手順を事実として書いてよい。

## 1. 「詳しく見えて中身がない」文（減点される型）

| 型 | 悪い例 | 直し方 |
|---|---|---|
| 見ただけで「確認できた」 | 「グラフは放物線を描き，理論通りに動作していることが確認できる」 | 何で確かめたかを書く（例：√I と V の直線性、数値の比較） |
| 設問の言い直し | 「0 Vでも微小な漏れ電流が存在することが確認できた」 | その値が大きいか小さいか（規格値・他の条件と比べる） |
| 数字のない「妥当」「概ね一致」 | 「概ね一致していると言える」 | 誤差を%で出す。設問が「誤差を求めよ」なら必ず出す |
| 原因の羅列 | 「製造ばらつき」「気温」「出力インピーダンスの整合」 | 自分のデータで大きさを見積もり、説明できる量かを確かめる |
| 反証できない主張 | 「仮に±5%なら最大11%ずれうるので範囲に収まる」 | 11%以内なら何でも収まる＝何も言っていない。向き・共通点などで絞る |
| 根拠のない数字 | 「±0.1 V程度のぶれが比に約10%の幅を与える」 | 数字の出どころを書く。書けないなら削る |
| 観察だけで終わる | 「飽和から戻るとき振動が見られた」 | 原因まで書けないなら、設問に関係なければ削る |
| まとめの決まり文句 | 「したがって〜が重要である」「この原因は以下のように考察できる」 | 削る |

## 2. 書くたびに自問する3つ

1. **その文、いる？** 設問に答えるのに必要か。なくても通じるなら削る。
2. **なんでそんなに言い切れるの？** 確かめたことと、仮定・推測を分ける。
   - 仮定は「〜と仮定すると，〜と合う」。
   - 確かめていないことは「〜は確かめていない／特定できていない」。
   - 「ほぼ説明できる」「〜である」と言い切るのは、確かめたときだけにする。
3. **考察どうしが矛盾していないか。**
   - 例：ある段落で「出力が約0.6 V低く測られていた」と結論したのに、別の段落で同じ実測値を「シミュレーションと一致」と書いた。

## 3. 理論の誤りとして指摘された例

- 「V_DSAT は V_GS に**比例**」→ V_DSAT＝V_GS−V_TH は比例ではない（一次関数）。
- しきい値電圧は「立ち上がり」で読まず、指導書どおり線形領域の直線を延ばして横軸との交点で求める。モデル値（SPICE の VTHO）とのずれにも触れる。
- 「線形領域に入ると I_DS の変動がキャンセルされる」→ 正しくは「g_m＝βV_DS が小さくなるため増幅率が下がる」。
- 誤差の原因に温度を挙げるなら、自分のデータの温度係数から、必要な温度差を見積もる（例：約60℃差が必要なら、室温差では説明できない）。
- 出力平均が電源電圧を超えるなど、**ありえない値**には必ず触れる（測定のずれのサイン）。
- 有効数字：入力が3桁なら、増幅率を5桁で書かない。

## 4. 数字の扱い

- **数字ごとに求め方を書く**：使った関数（Excel の SLOPE＝最小二乗法）、使った区間、補間の方法、誤差の式（式番号つき）、交点の求め方、画像からの読み取り（目盛り何V/divで読んだか）。
- **比べるものは同じ条件でそろえる**：シミュレーションを入力2〜3 Vの2点で読んだなら、実測の傾きも同じ区間で求める。飽和にかかる点は外す。
- **丸めをそろえる**：誤差は表に出した値から計算するか、表の桁を増やす（例：−1.03 から計算すると 3.0%、−1.027 からなら 2.7%）。
- 入力条件が違うもの（例：シミュレーション 2.0 Vpp、測定 1.0 Vpp）は、そのまま比べず増幅率などに直して比べる。
- 設問が「シミュレーションに対する誤差を表にまとめよ」なら、その表は**必須**（削らない）。

## 5. 見た目（電子情報工学実験IIのフォーマット）

- ひな形（report_format.docx）を使う。2段組・8ページ以内・PDFで提出。
- 図表の番号は**章ごと**（図2.1、表4.3）。図の説明は**図の下**、表の説明は**表の上**。説明文の下は**1行あける**。
- **すべての図に「図〇.〇 説明」をつける**。(a)(b)だけで済ませない（グラフは1枚ずつ別の図にする）。
- 表は**格子の罫線**。セルの文字が折り返さないよう列幅を調整する。
- 小見出し（2.1／(1)／考察1／①）は**字下げしない**。本文の段落だけ1文字下げる。
- 数式は**すべてWordの数式**にする。式番号は「⋯(2.1)」。分数を「/」の文字で書かない。
  - 長い計算を本文中に書かない。両端そろえで行がスカスカに崩れるため、1行ずつ独立した式にする。
- 記号は理論と実験で対応を書く（例：R1＝R_IN、R2＝R_OUT、V_X＝V_IRT）。用語の言い換え（仮想短絡＝仮想接地）は1回説明する。
- グラフは**Excelのグラフ**（Wordで「データの編集」ができる形）にする。
  - 軸ラベルと単位を入れ、グラフ内のタイトルは消す（図の説明文に書く）。
  - 角は四角、外枠なし。凡例はグラフの中。白黒でも区別できる線種・印にする。
  - 本人が自分のグラフの見た目を指定したら、それに合わせる。
- 写真は、各実験の回路図のすぐ後ろに「実験〇の基板」「実験〇の測定装置の構成」として入れる。
- 理論は、共通テキストの内容をまとめ直し、図は指導書から切り出して出典 [1] をつける。指導書で空欄の式は導出して埋める。
- Wordの■（行頭の黒い点）は「次の段落と分離しない」設定の編集記号で、印刷されない。

## 6. 道具と環境のメモ

- Googleドライブから取り込めるのは **10MB まで**。大きいWordは、同じ内容のPDFか、チャットへの直接アップロードを頼む。
- PDFにして数式を確かめるには `libreoffice-math` が必要（`make_outputs.py` が自動で入れる）。
- LibreOfficeで見ると、数式の括弧が「|」に見えることがある。中身（OMML）は正しいので、Wordでの見え方を本人に確かめてもらう。
- Word作成の部品は `scripts/docx_parts/` にある（数式・Excelグラフ・表・図・小見出し）。使い方は `scripts/docx_parts/README.md`。
