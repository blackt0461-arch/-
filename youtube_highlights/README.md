# YouTube 配信 ハイライト(面白かったシーン)抽出ツール

YouTube の配信アーカイブ(または通常動画)の URL を渡すと、視聴者の反応を解析して
「面白かったシーン」のタイムスタンプを、コメント欄にそのまま貼れる形式で出力します。

```
$ python find_highlights.py "https://www.youtube.com/watch?v=XXXXXXXXXXX"
■ 【雑談】まったり話す配信
面白かったシーン 6 件

9:40 😂 爆笑「草」「www」「腹筋崩壊」
24:40 😲 驚き「えぇ!?」「!?」「まじか」
39:40 😂 爆笑「lol」「草草草」「www」
...
```

## セットアップ

```bash
pip install -r requirements.txt       # yt-dlp
# 音声解析 (--audio) と音声照合 (--match-audio) を使う場合のみ
pip install numpy && (ffmpeg をインストール)
```

Python 3.10 以上。チャット・コメント・ヒートマップの解析は標準ライブラリのみで動きます。

## 使い方

```bash
python find_highlights.py URL                 # 基本
python find_highlights.py URL -n 15 -v        # 15 件、スコア・根拠・リンク付き
python find_highlights.py URL -f json         # JSON 出力
python find_highlights.py URL --audio         # 音声の盛り上がりも使う (DL するので重い)
python find_highlights.py URL -e              # 実際の切り抜き動画と照合して正確性を測る
python find_highlights.py URL -e --match-audio  # 概要欄に時刻が無い切り抜きも音声で位置を特定

# 保存済みデータから再解析 (ネット不要・パラメータ調整用)
python find_highlights.py --info-json data/ID.info.json --chat-file data/ID.live_chat.json -v
python find_highlights.py ... --curve curve.csv   # スコア曲線を CSV に出力 (グラフ化用)
```

主なオプション:

| オプション | 既定値 | 意味 |
|---|---|---|
| `-n/--top` | 自動 (10 分に 1 件, 3〜20) | 出力件数 |
| `--chat-delay` | 8 秒 | 出来事からチャットが反応するまでの遅延 |
| `--pre-roll` | 10 秒 | タイムスタンプを前倒しする秒数(前振りから見られるように) |
| `--min-gap` | 60 秒 | ハイライト同士の最小間隔 |
| `--threshold` | 1.5 | 統合スコアの閾値。少ない時は下げる |
| `--weight NAME=W` | 下表 | シグナルの重み変更 |
| `--max-comments` | 500 | 取得するコメント数(0 で無効、多いほど遅い) |
| `--workdir` | `data` | 取得データの保存先。2 回目以降は保存済みデータを再利用 |
| `--no-html` / `--no-open` | | グラフ付きレポートを作らない / 自動で開かない |

実行すると `report_<動画ID>.html` が作られ、ブラウザで自動的に開きます(次の章)。

## グラフ付きレポート

- **盛り上がりスコアの推移**: 青い線。点線がしきい値、黒い丸の数字が検出したシーン(スコア順位)。
- **実際に切り抜かれた場面**(評価時のみ): グラフ下のオレンジの帯。濃いほど多くの切り抜きに使われた場面。
  検出シーンの上の ✓ / ✗ が当たり・外れ。
- **シグナルごとの内訳**: チャットの反応・コメント・よく再生されている部分などを個別に表示。
  どの情報がスコアを押し上げたかが分かります。
- グラフ上で**ドラッグすると拡大**、**クリックするとその時刻の動画**が開きます。マウスを乗せると詳細を表示。
- 検出シーン・切り抜き場面の一覧表(時刻はクリックで動画へ)。

## 正確性の評価 (`-e`)

「検出したタイムスタンプが、実際にどのくらい切り抜かれているか」を測ります。
視聴者が作った**切り抜き動画を正解データ**として使います。

### 切り抜き動画の集め方

1. YouTube を「動画 ID」「配信タイトル + 切り抜き」「チャンネル名 + 切り抜き」で検索(各 `--max-clips` 件)。
2. 元配信より前の動画・元配信より長い動画は除外。
3. 元配信のどこを切り抜いたかを特定:
   - **概要欄の時刻リンク**: `youtu.be/元配信ID?t=1234` のようなリンク(最も確実)。
   - **概要欄の時刻表記**: 元配信 ID や「元配信」「本編」を含む行の `1:23:45` など。
   - **音声照合**(`--match-audio`): 切り抜きと元配信の音声を照合。0.1 秒ごとの 24 帯域の
     スペクトル形状(音量差・一定の BGM を打ち消す処理つき)を作り、切り抜きを 10 秒ずつの
     断片に分けて元配信全体との正規化相互相関を FFT で計算。相関が高く、他の位置より
     突出している断片だけを採用するので、編集で場面をつないだ切り抜きでも複数の区間を特定できます。
   - 位置が分からない切り抜きは評価に使いません。
4. 同じ場面を使った切り抜きは 1 つの「切り抜き場面」にまとめます(本数も記録)。

正解を自分で用意する場合は `--truth 正解.csv`(1 行 1 シーン: `開始,終了,メモ`。時刻は秒か `1:23:45`)。
切り抜きの URL を直接渡す場合は `--clip URL`(複数回指定可)。

### 指標

| 指標 | 意味 |
|---|---|
| 適合率 | 検出したシーンのうち、実際に切り抜かれていた割合 |
| 再現率 | 切り抜かれた場面のうち、検出できた割合(切り抜き本数で重み付けした値も表示) |
| ランダム比 | 適合率 ÷「同じ件数をランダムな時刻に置いた時の期待適合率」。切り抜き場面が多い配信ほど偶然でも当たりやすいので、その分を差し引いた実力 |
| タイミング誤差 | 当たったシーンの出力時刻と切り抜き開始のずれ(中央値) |
| 上位 k 件の適合率 | スコア上位 k 件に絞った時の適合率 |

検出区間の前後 `--tolerance`(30 秒)以内に切り抜き場面があれば「当たり」です。

### 注意

- 見つかる切り抜きは一部なので、**適合率は実際より低めに出ます**(切り抜かれていない ≠ 面白くない)。
- 切り抜きは「面白い」以外の理由(告知・歌・感動シーン)でも作られます。
- 音声照合は元配信と切り抜き全部の音声をダウンロードするので時間がかかります。

## アルゴリズム

### 全体像

```
URL ──yt-dlp──┬─ ライブチャット (リプレイ) ─┬─ 反応スコア    (笑い/驚き/…)
              │                             ├─ チャット速度  (ユニーク投稿者数)
              │                             └─ スパチャ
              ├─ Most Replayed ヒートマップ ── 再生集中度
              ├─ コメント欄 ──────────────── タイムスタンプ言及
              └─ 音声 (任意) ─────────────── 音量の急上昇
                        │
          5 秒 bin の時系列に変換 → 平滑化 → 遅延補正
                        │
          ローカルベースラインに対するロバスト z スコア
                        │
          重み付き和 + 一致ボーナス = 統合スコア
                        │
          ピーク検出 → 非極大抑制 → 区間推定 → ラベル付け → 出力
```

「面白いシーン」を直接判定するのは難しいので、**視聴者が面白いと感じた痕跡**を
複数の独立した情報源から集め、それらが「普段よりどれだけ突出しているか」で判断します。

### 1. シグナルの抽出

すべて `bin_size`(既定 5 秒)ごとの時系列にします。

**(a) 反応スコア (reaction, 重み 0.35)** — 最も重要なシグナル。
チャット本文を NFKC 正規化(全角 `ｗ`→`w` など)した上で、反応語辞書で分類します。

| カテゴリ | 例 | 面白さへの重み |
|---|---|---|
| clip (切り抜き希望) | 切り抜き, ここすき | 1.2 |
| laugh (笑い) | 草, www, 笑, ワロタ, lol, 😂 | 1.0 |
| surprise (驚き) | !?, えぇ, まじ, wtf | 0.8 |
| hype (盛り上がり) | うおおお, 神, ナイス, すげぇ, 🔥 | 0.7 |
| cute (てぇてぇ) | てぇてぇ, 尊い, かわいい | 0.6 |
| applause (拍手) | 8888, 👏, おめでとう | 0.5 |

- 単語の「w」は英単語 (wow, what) と区別するため、前後が英字でない場合だけ笑いと判定。
- `wwwwww` `草草草` のように長いほど強度を上げる: `強度 = 1 + 0.15 × 繰り返しの余剰文字数 (上限 10)`。
- 1 メッセージの値 = 最も強いカテゴリ + その他カテゴリの 30%。
- **同一ユーザーは 1 bin につき 1 回(最大値)だけ数える**。1 人の連投スパムで誤検出しないため。

**(b) チャット速度 (activity, 0.10)** — bin 内の**ユニーク投稿者数**。反応語を使わない盛り上がり
(英語圏・独自スラングなど)を拾う補助シグナル。

**(c) スパチャ (money, 0.05)** — スーパーチャット/メンバー加入。金額は `1 + log(1 + 金額/100)` で圧縮。

**(d) Most Replayed (heatmap, 0.20)** — YouTube が提供する「よく再生されている部分」。
多くの人が何度も見返した場所なので、面白いシーンと強く相関します。
冒頭 1% は「最初から再生」による偽ピークなので無視します。

**(e) コメント欄のタイムスタンプ (comments, 0.25)** — 「12:34 ここ好き」のような言及を抽出し、
σ=10 秒のガウス核で時系列に広げます。
`重み = (1 + log(1 + いいね数)) / √(そのコメント内のタイムスタンプ数)`。
目次のようにタイムスタンプを大量に並べたコメントは 1 件あたりの重みが下がり、
本文に「草」などの反応語があれば ×1.5。

**(f) 音声 (audio, 0.10, `--audio` 時のみ)** — 8kHz モノラルに変換し、bin ごとの RMS 音量 (dB)。
笑い声・叫び声による急な音量上昇を、直近 60 秒の基準と比べて検出します。

### 2. 前処理

1. **平滑化**: チャット系は ±1 bin(15 秒窓)の移動平均。反応は数秒〜十数秒にわたって続くため。
2. **遅延補正**: チャットは出来事の数秒後に書き込まれるので、チャット系シグナル全体を
   `chat_delay`(8 秒)だけ過去方向にずらす。ヒートマップとコメントは補正不要。

### 3. ロバスト正規化(ローカルベースライン)

配信ではチャット量が時間とともに大きく変わります(序盤は少なく、終盤やゲームのクライマックスで増える等)。
全体平均と比べると「人が多い時間帯」ばかり選ばれてしまうので、**その時間帯の普段の値**と比べます。

```
z(t) = max(0, (x(t) − median_W(t)) / scale_W(t))
scale_W(t) = max(1.4826 × MAD_W(t), √(median_W(t) + 1))
```

- `median_W`, `MAD_W`: 前後 5 分(`baseline_window`)の中央値と中央絶対偏差。
  平均・標準偏差ではなく中央値・MAD を使うので、盛り上がりそのものに基準が引っ張られにくい。
- `√(median + 1)` はポアソン揺らぎの下限。チャットが過疎な時間帯に「0 件→2 件」程度で
  z が跳ね上がるのを防ぎます。
- ヒートマップは既に相対値なので全体の中央値/MAD で正規化。
  コメント言及はまばら (ほぼ 0) で MAD が使えないため `8 × log(1+v) / log(1+max(v_max, 7))`。
- 各 z は上限 8 でクリップ(1 つのシグナルだけで決まらないように)。

### 4. 統合スコア

```
score(t) = Σ_k  w_k / Σ(利用可能な w) × z_k(t)
```

- 取得できなかったシグナル(チャット無効の動画、ヒートマップ未生成など)は除外して重みを再正規化。
  そのため **チャットのない通常動画でもコメント欄とヒートマップだけで動作** します。
- **一致ボーナス**: z ≥ 2 のシグナルが m 個(m≥2)同時に立っていれば `× (1 + 0.15 (m−1))`。
  独立した情報源が同じ時刻を指しているほど信頼できるため。

### 5. ピーク検出と区間推定

1. 局所最大かつ `score ≥ threshold` の bin を候補にする。
2. **非極大抑制 (NMS)**: スコア順に採用し、既に採用したピークから `min_gap`(60 秒)以内の候補は捨てる。
   1 つの盛り上がりから複数のタイムスタンプが出るのを防ぐ。上位 `top` 件まで。
3. **区間推定**: ピークから左右に、スコアがピークの 40% 以上である範囲を広げる(片側最大 90 秒)。
4. **出力時刻 = 区間の開始 − pre_roll(10 秒)**。
   面白いシーンはオチの直前の「振り」から見たほうが楽しめるため、反応のピークよりかなり前を指します。

### 6. ラベル付け

区間内(遅延分ずらして)のチャットの反応カテゴリを重み付きで集計し、最多のものをラベルに
(`😂 爆笑` / `😲 驚き` / `🔥 盛り上がり` / `✂️ 切り抜き候補` / `💕 てぇてぇ` / `👏 拍手`)。
反応語チャットが無い場合は `📈 注目シーン`。最も多く書き込まれた短いチャット上位 3 つを添えます。

## 構成

```
find_highlights.py      エントリポイント
highlights/
  chat.py               live_chat.json のパース、反応語辞書と分類
  signals.py            時系列化・平滑化・ロバスト z・各シグナル生成
  detect.py             統合スコア・ピーク検出・区間推定・ラベル付け
  fetch.py              yt-dlp によるデータ取得 (情報/チャット/コメント/音声)
  report.py             テキスト・JSON・CSV 出力
  clips.py              切り抜き動画の検索と、元配信上の位置の特定
  audiomatch.py         音声照合 (スペクトル特徴 + FFT 相互相関)
  evaluate.py           正確性の評価 (適合率・再現率・ランダム比など)
  visualize.py          グラフ付き HTML レポート
tests/test_highlights.py
tests/test_evaluate.py
```

テスト(合成チャットで、ベースラインのドリフトや 1 人の連投スパムがあっても
仕込んだ出来事だけを検出できることを確認):

```bash
cd tests && python -m unittest discover -v
```

## 制限・注意

- ライブチャットのリプレイが無効な配信ではチャット系シグナルは使えません(コメント・ヒートマップ・音声で代替)。
- Most Replayed は再生数が少ない動画では YouTube 側で生成されません。
- 反応語辞書は日本語の配信文化(草・ｗ・てぇてぇ等)を中心にしています。`highlights/chat.py` の `LEXICON` に追記して調整できます。
- コメント取得は件数が多いと時間がかかります(`--max-comments` で調整)。
- YouTube の利用規約の範囲内で、個人的な用途で使ってください。
