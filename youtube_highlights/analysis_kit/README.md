# 切り抜き動画の伸び方 分析キット

「どんな切り抜き動画が再生数を取れるか」を分析するための手順・定義・データ・結果をまとめたものです。
ほかの人(ほかのアカウントの Claude を含む)が同じ方法で分析し、結果を足し合わせられるようにしてあります。

- 分析結果 … `results/`
- 再現スクリプト … `reproduce.py`(ネット不要。同梱データから同じ数字が出ることを確認できる)

## 1. 分析は 2 段階

| 段階 | 調べること | 必要な情報 | 実行 | 所要時間 |
|---|---|---|---|---|
| A. 傾向分析 | 動画の長さ・タイトルの特徴と再生数の関係 | 動画の一覧情報(再生数・長さ・タイトル・投稿日) | `python analyze_trends.py 名前…` | 数分 |
| B. 配信からの学習 | 元配信のどんな場面(チャットの盛り上がり方など)が切り抜かれ・伸びるか、前振り・余韻の長さ | A に加えて、各切り抜きの概要欄と、元配信のチャット・コメント・字幕 | `python learn_clips.py 名前…` | 配信者 1 人あたり数十分 |

B は動画ごとの詳細情報を取得するため、**家庭の回線で実行**してください(クラウドのサーバーからは YouTube のボット判定で拒否されます)。
ボット判定を回避する工夫(Cookie の流用、取得方式の偽装など)はしないでください。

## 2. A. 傾向分析の方法

### 2.1 データの集め方
1. 配信者名ごとに「`名前 切り抜き`」を YouTube で検索する(再生数順・新しい順 各 100 件)。
2. 結果に多く出てくる **切り抜きチャンネル** を上位から選ぶ(配信者本人の公式チャンネルは除く)。
3. 各チャンネルの **動画一覧(新しい順 100 本)** を、投稿日(「3 日前」などからの概算)付きで取得する。

検索結果をそのまま使わないのは、検索が「人気順の上位」「新着」に偏っていて、チャンネルの普段の動画を表していないためです。

### 2.2 比べ方(回帰モデル)

```
log10(再生数) = チャンネル固有の水準 + b_age × log10(投稿からの日数) + Σ b_k × 特徴_k + 誤差
```

- **チャンネル固定効果**: チャンネルごとに平均を引いてから最小二乗法(リッジ λ=1)。チャンネルの大きさの違いを消す。
- **10^b_k** が「その特徴があると、同じチャンネルの普段より何倍か」。
- 基準は「10〜20 分の通常動画」。長さは 〜1 分 / 1〜3 / 3〜6 / 6〜10 / 10〜20 / 20 分〜 の区分。
- タイトルの特徴: 【】・「」・ｗ/草・！？・→・…・まとめ/総集編・手描き/アニメ・英語・数字・#・【】内の名前が 4 人以上・長さ(30 文字未満 / 80 文字以上)。
- 除外: 投稿 7 日未満(再生数が伸びている途中)、動画が 10 本未満のチャンネル、出現 15 本未満の特徴。
- **不確かさ**: チャンネル単位のブートストラップ(300 回)で 95% 区間。区間が 1 をまたがない特徴を「はっきりした差(★)」とする。

### 2.3 方法の検証(合成データ)
答えの分かっている合成データ(30 チャンネル × 60 本、ショート ×3・1〜3 分 ×0.5・日数の効果あり)で確認済み。

| 確認 | 結果 |
|---|---|
| 仕込んだ効果の復元 | ショート ×2.92(真値 3)、1〜3 分 ×0.49(真値 0.5)、日数 10 倍で ×2.06(真値 2.0) |
| 効果ゼロの特徴を「★」と誤判定する率 | 40 回中 2 回(5%。95% 区間の想定どおり) |
| 真値が 95% 区間に入る率 | 20 回中 18 回 |

90% 区間では誤判定が 20% と多かったため、95% 区間を採用しています。

## 3. A の結果(2026-10-26・50 チャンネル・4,475 本)

対象: 兎田ぺこら / 宝鐘マリン / さくらみこ / 戌神ころね / 星街すいせい / 猫又おかゆ / 月ノ美兎 / 葛葉 / 壱百満天原サロメ /
加藤純一 / 釈迦 / k4sen / ホロライブ / にじさんじ の切り抜きを多く出しているチャンネル。

| 特徴 | 再生数の倍率 | 95% 区間 | 本数 |
|---|---|---|---|
| ★ タイトルに「手描き / アニメ」 | ×1.64 | 1.07〜2.15 | 685 |
| ★ 英語タイトル(海外向け) | ×1.61 | 1.31〜2.07 | 1,095 |
| ★ 長さ 20 分以上 | ×1.47 | 1.33〜1.61 | 1,505 |
| ★ 【】内に 4 人以上の名前(コラボ) | ×1.24 | 1.10〜1.40 | 1,044 |
| ★ 「」でセリフを引用 | ×1.20 | 1.01〜1.36 | 302 |
| → (展開の予告) | ×1.28 | 0.95〜1.84 | 29 |
| ｗ / 草、！？、#、数字、【】の有無 | ほぼ ×1(はっきりしない) | | |
| ★ 長さ 6〜10 分 | ×0.87 | 0.77〜0.96 | 629 |
| 長さ 1〜3 分 / 3〜6 分 | ×0.83 | 区間が 1 をまたぐ | |

**読み方の注意**
- 「英語タイトル」「手描き」は、そういう動画を作る特定のチャンネルの特徴が混ざっている可能性があります(チャンネル内の比較なので
  ある程度は除けていますが、同じチャンネル内でも英語版を別に作るなど)。
- **投稿日数の効果が負(日数 10 倍で ×0.80)** になりました。チャンネルが成長中で、古い動画ほど登録者が少ない時期に出た影響と考えられ、
  日数の補正は完全ではありません。
- **ショートは分析できていません**: 現在の yt-dlp ではチャンネルのショート一覧が取得できず(「ショート欄が無い」と返る)、
  検索結果でもショートはほとんど出てきません。
- 相関であって因果ではありません(例: 長いまとめ動画は、もともと人気の場面を集めているから伸びる、など)。

この結果は自動切り抜きに次のように使っています: 投稿用タイトルの提案を「」のセリフ引用 +【配信者名/切り抜き】の形にする、
複数の場面をつないだ「まとめ動画」を作る。

## 4. B. 配信からの学習の方法

1. A と同じ検索で切り抜きを集め、**概要欄から元配信と時刻** を特定(`youtu.be/ID?t=秒` など)。時刻が無い切り抜きは、
   元配信と切り抜きの **自動字幕を照合**(文字 5-gram の一致から時間のずれに投票)して特定。
   元配信の 10 分以上を使ったまとめ動画は除外。
2. 元配信ごとにチャット・コメント・よく再生された部分を取得し、盛り上がり解析を行う。
3. **切り抜かれた区間(正例)** と、同じ配信の **切り抜かれていない同じ長さの区間(負例、1 本につき 3 区間)** について、
   次の特徴を記録する。

| 特徴 | 内容 |
|---|---|
| score_max / score_mean | 統合した盛り上がりスコアの最大・平均 |
| reaction_* / activity_* | チャットの反応(笑い・驚きなど)・チャット速度(人数)の z スコアの最大・平均 |
| heatmap_max / comments_max / money_max | よく再生された部分・コメント欄での時刻の言及・スパチャ |
| n_peaks | 区間内の盛り上がりの山の数 |
| chat_rate_ratio | 区間のチャット量 ÷ 配信全体の 1 分あたり中央値 |
| share_laugh 〜 share_clip | 反応のうち 笑い・驚き・盛り上がり・てぇてぇ・拍手・「切り抜き希望」の割合 |
| position / length_min | 配信内の位置(0〜1)・区間の長さ |

正例には、切り抜きの再生数・投稿日・チャンネル登録者数・長さ、**前振り(区間の始まり〜最初の山)・余韻(最後の山〜区間の終わり)** も記録。

4. 学習
   - **切り抜かれやすさ**: 正例 vs 負例のロジスティック回帰(特徴を標準化、L2 正則化)。精度は **配信単位の 5 分割交差検証の AUC**
     (学習に使っていない配信で測る)。盛り上がりスコアだけの AUC も並べて、学習の上積みを確認する。
   - **伸びやすさ**: 正例で `log10(再生数) ~ log10(日数) + log10(登録者数) + 長さ + 特徴` のリッジ回帰。
   - **作り方**: 登録者数と日数で説明した残りが上位半分の切り抜きの、前振り・余韻・長さの中央値。
5. 結果は `model.json` に保存され、アプリが自動で使う(場面を「切り抜かれやすさ」順に選ぶ・前振りと余韻の長さ)。

合成データでの確認: 仕込んだ「笑いが多いと切り抜かれやすく、再生数 ×1.58」を、AUC 0.90・×1.56 で復元。

## 5. データの形式

### A: `data/channel_rows_*.json`
```json
{"meta": {"collected": "2026-10-26", ...},
 "rows": [{"id": "動画ID", "channel_id": "UC...", "channel": "チャンネル名", "subs": 23700, "kind": "video",
           "views": 173000, "duration": 1085.0, "title": "...", "age_days": 61.2}, ...]}
```
`analyze_trends.py` が `trends/channels_日時.json` に出すファイルは `rows` の中身だけ(リスト)。どちらも `reproduce.py` で読めます。

### B: `learn/dataset.jsonl`(1 行 1 区間)
```json
{"clip_id": "切り抜きID or null", "stream_id": "元配信ID", "label": 1, "start": 1234.0, "end": 1300.0,
 "views": 52000, "duration": 70, "upload_date": "20261020", "subs": 120000, "channel_id": "UC...",
 "lead": 12.0, "tail": 6.5, "method": "link", "streamer": "兎田ぺこら", "stream_duration": 10800,
 "features": {"score_max": 6.1, "...": 0.0}}
```
チャットの本文は保存しません(特徴量だけ)。
