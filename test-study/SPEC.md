# テスト勉強（test-study）

大学の中間・期末テストの勉強アプリ。使うのは本人ひとり。スマホ中心。
公開先：https://blackt0461-arch.github.io/-/test-study/

## 決まったこと（2026-11 の聞き取り）

- 問題は **Claude がグーグルドライブのレジュメを読んで作る**。本人に頼まれたときに作る（自動ではない）。アプリの中で AI は使わない（お金がかからない）。
  - レジュメの場所：ドライブ「2026年後期」フォルダ（id `1bzzUiiheg72MBtZzh73Hm1PKrLw_iEHq`）の中に授業ごとのフォルダ。ファイル名は `第NN回_月-日_連番`。
- 分け方：**授業 → テスト（中間・期末）**。範囲は授業の回（第N回）でしぼれる。
- 問題の量：レジュメの内容を**すきまなくカバー**できるだけ作る。
- 勉強のしかた：ぜんぶ混ぜる／単語カード／小テスト（選択・穴うめ・計算＝自動採点）／記述・説明／まちがい復習。1回に解く数は毎回えらぶ（5・10・20・ぜんぶ）。
- 記述：スマホで打つ・紙に書いて写真、どちらもできる。お手本と「入れるべきポイント」を見て自分で⭕🔺❌。答えは保存し、あとで Claude にも採点してもらえる。
- 計算：答え（数字）を入れて自動採点し、解き方を出す。
- 持ち込み可のテストは「まとめシート」（印刷できる）も作る。電子回路I は A4 片面1枚（印刷すると2段組み・小さめの文字で1ページに収まる）。
- **記憶曲線（1.2.0）**：`js/memory.js`。問題ごとに「記憶の安定度 S（日）」を持ち、思い出せる確率 $R=0.9^{経過日数/S}$（忘却曲線）。
  - 正解：思い出しにくい時ほど S が大きくのびる（間隔反復）。正解率が低い（むずかしい）問題はのびにくい。まちがい：S を 1/4 に。おしい：0.8 倍。
  - 「覚えている」＝いま R≥0.9。R<0.9 になったら復習。
- **今日の勉強**：最初の画面に、テストごとの「テストの日に覚えている（予想）◯%」「今日の目標◯問・済◯問」。
  - 毎日＝復習（R<0.9 の問題、忘れかけ順）＋新しい問題（まだ解いていない問題を前日までの日数で割った数、授業の回の順）。目標はその日最初に計算した数で固定。
  - 前日＝テストの日に R<0.9 になりそうな問題を総復習。当日＝忘れかけている問題だけ見直し。
  - 1回は10問ずつ。「続ける（今日あと◯問）」。目標を終えたら「もっとやる」。
  - テストの日はテスト画面で変えられる（延期に対応）。
  - テスト画面に、回ごとの「いま覚えている度」と、しくみの説明。
- **ドライブ連携（1.2.0）**：`server/Code.gs`（Google Apps Script。本人がドライブで1回だけ準備）と `js/cloud.js`。
  - 受け口の URL と鍵は `js/cloud.js` の BUILTIN に入れてある（本人の希望で入力も合言葉もなし。開くと自動でつながる）。受け口は最初に来た鍵を登録する。切るボタンや設定画面はなく、最初の画面の下に保存した時刻だけを出す。
  - ドライブ「テスト勉強」フォルダ：`記録（さわらないでください）.json`（問題ごとに新しく解いたほうを残してあわせる）、`記述の答え/<授業・テスト>/日時_id.json` と写真 `.jpg`。
  - 記録は先に端末に保存し、変わって4秒後・アプリを閉じるとき・開いたときにドライブとあわせる。
  - Claude は Drive の記録と記述の答えを読める（「記述の答えを採点して」に使う）。
- **見た目（1.3.0）**：紺〜むらさきのグラデーション。ホームは見出し（連続日数・今日の問題数）＋テストのカード（あと◯日・テスト日の予想の円メーター・今日の目標）。下にタブ（ホーム／記録）。勉強のしかたはアイコンのタイル、「次へ」は画面の下に固定。明るい／暗いモードは端末の設定に合わせる。
- **追加の機能（1.3.0）**
  - ⭐あとで見る：問題に⭐をつけ、「あとで見る」でまとめて解く。⭐は記録の中に `★/<問題のkey>` という項目で持つ（ドライブの受け口を変えずに同期するため）。
  - 模擬テスト：選択・穴うめ・計算から最大15問、1問1分の時間制限。答えは最後にまとめて採点し、あなたの答えと正解を並べる。結果は記録に入る。
  - 問題一覧：ことばでさがす、⭐・まちがい・忘れかけ・まだ でしぼる。答えと解説を開いて見られる。
  - 記録のタブ：連続日数、合計、正解率、覚えている問題数、15週のカレンダー、テストごとの覚えている度、苦手な問題トップ10（まとめて解ける）。
  - 正解・まちがいで端末が短くふるえる（対応している端末だけ）。
- 名前は「テスト勉強」で仮。あとで決める。

## 問題データの書き方

- `data/courses.json`：授業とテストの一覧。`{ "courses": [ { "id", "name", "tests": [ { "id", "name", "date"(任意 YYYY-MM-DD) } ] } ] }`
- `data/<授業id>/<テストid>.json`：`{ "note"(任意), "sheet"(任意・まとめシートのファイル名), "questions": [...] }`
- 問題の形（すべて `id`（テスト内で一意・変えない。記録とつながる）、`lecture`（例「第3回」）、`q`、任意で `explain`）
  - `card`：`a`（答え）
  - `choice`：`choices`（配列）、`answer`（正解の番号、0から）
  - `fill`：`answers`（正解として認める書き方の配列。ひらがな・別名も入れる）
  - `calc`：`answer`（数）、`tol`（ゆるす誤差の割合、ふつう 0.01）、`unit`、`answerText`（任意。表示用）
  - `written`：`model`（お手本）、`points`（入れるべきポイントの配列）
- どの問題にも書けるもの（任意）：`fig`（図のファイル。例 `fig/cs-res.svg`）、`figAfter: true`（図が答えを教えてしまう問題は、答えたあとに図を出す）、`howto`（上に出す「この問題でやること」を形式ごとの決まり文句から変えたいとき）。
- 問題の上には、形式ごとに「この問題でやること」を小さく出す（カード＝思い浮かべてから答えを見る、選択＝1つ選ぶ など）。カードの問題文は、ことばだけにせず「〜とは何か、説明しよう」のような問いかけにする。
- 図は `tools/figs_denshi1.py` で SVG を作る（回路図・グラフ。白い背景）。図を足すときはこのファイルに描いて実行する。
- 数式は `$...$`（文中）と `$$...$$`（1行）。KaTeX で表示する。JSON の中では `\` を `\\` と書く。
- まとめシート：`data/<授業id>/<ファイル名>.html`（`<h1>〜` から始まる中身だけ。印刷で A4 に収まる量を目安）。

## しくみ

- ふつうの HTML と JS（`js/app.js` 画面、`js/store.js` 記録）。組み立て作業なし。
- 記録：`localStorage` の `ts_records_v1`（問題ごとの回数・正解数・まちがい復習に入っているか）。記述の答えと写真は IndexedDB `test-study`。
- 速く開くために（1.5.0）：問題データ（courses.json・テストの JSON）は localStorage にもとっておき、2回目からはそれですぐ画面を出して、裏で新しいデータを確かめる（変わっていればホームを表示しなおす）。数式の道具（KaTeX）は数式が出る画面ではじめて読む（ホームが出たあとに先読み）。フォントは画面を待たせない読み方。アプリの部品は modulepreload でまとめて読む。
- 問題の `id` を変えると記録が切れるので、直すときも `id` は残す。

## 1.6.0 で足したこと

### 記録のしくみ（複数の端末でも合わさる）
- `js/store.js`。答えるたびに「できごと」`ev/<端末>/<番号>` = {q, r, at, h, s} を残し、問題ごとの状態（回数・正解・記憶の安定度 S）は、できごとを古い順にたどって計算しなおす。
- ⭐（`★/`）、Claude の採点（`採/<答えのuid>`）、その日の目標（`tg/`）、テストの日（`dt/`）も同じ表に入れる。どれも t（最後に変えた時刻）を持ち、ドライブの受け口は「キーごとに t が新しいほう」を残す（受け口のコードは変えていない）。
- ドライブへは、変えたものだけを送る（`ts_dirty_v2`）。電波がもどったら（online）・アプリを閉じるとき・開いたときに送る。
- 1.6.0 より前の記録は、開いたときに引っ越す（問題ごとの状態はそのまま土台にし、そのあとのできごとを足す）。
- 最後にまちがえた問題は、「いま覚えている度」を 50% までしか数えない。

### アプリをスマホにとっておく
- `sw.js`（サービスワーカー）。部品はとっておいたものをすぐ出して裏で入れかえ、問題データはネット優先。電波がなくても開ける。
- **新しい版を出すときは、`sw.js` の VERSION、`index.html` の `?v=`、`js/app.js` の APP_VERSION をそろえて上げる。** 上がると新しい部品に入れかわり、ホームにいるときに自動で開きなおす。

### 計算問題のヒント
- 問題に `hints`（配列）を書くと「ヒントを見る」ボタンが出る。ヒントなしで正解＝正解、ヒント1つで正解＝おしい、ヒント2つ以上で正解＝まちがい（表示は「ヒントで解けた」）。できごとに h（使った数）と s（ヒントありで正解）を残す。

### ふりかえりレポート（記録のタブから）
- 今までの全部：勉強した日・解いた数・正解率・最長の連続日数・1日の平均・まちがいから覚えた問題、正解率の移り変わり（2週間までは日ごと、それより長いと週ごと）、回ごと・形式ごと・時間帯ごとの正解率、ヒントと採点、まだ覚えきれていない問題、「次にやるとよいこと」。

### Claude による記述の採点（本人に「採点して」と言われたら）
1. ドライブ「テスト勉強/記述の答え/<授業・テスト>/」の `日時_<uid>.json`（答え）と `.jpg`（写真）を読む（Google Drive のツール）。
2. `python3 test-study/tools/drive.py graded` で採点ずみの uid を見て、まだのものだけ採点する（証明書は `SSL_CERT_FILE=/root/.ccr/ca-bundle.crt`）。
3. 問題のお手本・ポイント（`data/<授業>/<テスト>.json`）とレジュメをもとに採点し、`[{uid, q, grade: ok|mid|ng, score: 0-100, comment, missing: [...], better, self, yours, at}]` の JSON を作る。
4. `python3 test-study/tools/drive.py post 採点.json` で書きこむ。自己採点より低いときは、その問題がまた早めに出るよう「できごと」（`ev/claude/<uid>`）も入る。
5. アプリは次に開いたとき（同期したとき）に、最初の画面に「Claude の採点が届きました」と出し、「書いた答え」に点数・コメント・足りなかったポイント・こう書くとよい を出す。

## 1.7.0 授業（スライド）

- テスト画面の「授業で学ぶ」から。電子回路I は 第0回（準備：電気と数学のきほん）〜第6回 の7本・262枚・確認クイズ41問。中学・高校生が予備知識ゼロでも、見終わればその回の問題にすべて答えられるように作る。
- 中身：`data/<授業>/lessons/l<N>.json` = {id, lecture, title, sub, minutes, slides:[...], covers:{問題id:[スライド番号]}}。
  - スライドの種類：cover / text / analogy（たとえ）/ formula（大事な式。tex）/ point（ここを覚える）/ flow（流れ）/ table / steps（導き方）/ quiz（確認クイズ）/ summary。どれにも fig（図）をつけられる。
  - 本文の書き方：`**太字**` `==マーカー==` 行頭 `- ` で箇条書き、`$...$` は数式。
  - covers：その回の問題がどのスライドで説明されているか。全問がどこかの授業に入っていること。
- 授業を足したら `python3 test-study/tools/lessons.py <授業> <テスト>` を実行する。テストの JSON の `lessons` に登録され、カバーされていない問題・おかしな所を表示する。
- 見た目：1画面1スライド、横スワイプ・「次へ」でめくる。どこまで見たかは記録（`ls/<授業>/<テスト>/<id>`）に残り、ドライブで同期。続きから見られる。
- 最後のスライドで「この回の問題を解く」「次の授業」。問題の答え合わせ画面には「この問題の授業を見る」（covers のスライドへ飛ぶ）。
- 授業を書くときの共通の指示（作業役に渡したもの）は、`tools/` ではなく会話の中で作った。書き方の要点はこの節のとおり。
