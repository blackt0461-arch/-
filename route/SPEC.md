# いどうナビ（route/）設計書

2026-11-10 本人と決定。公開先の予定：https://kotetsuworks.com/route/

## 目的
1日の予定を入れると、予定と予定の間の **移動（出発時刻・かかる時間・乗りかえ）** と **すき間（休憩できる時間）** を自動で出す。

## 移動時間の出し方（本人の希望：完全自動・Yahoo!乗換案内の結果）
1. **Yahoo!乗換案内の検索結果を自動で読む**（本人の決定 2026-11-10）。
   - 本人いわく、LINEヤフーに問い合わせて許可を得ている（文面は未確認）。
   - 調べた事実：Yahoo! に公開の乗りかえ API はない（developer.yahoo.co.jp/webapi/map/）。LINEヤフー共通利用規約に個人利用の例外の記載はない（14条 目的外利用の禁止、15条(5) BOT 等による不正な操作の禁止）。robots.txt は /search/result/ を許可、/api/ などは不許可、Claude などの AI は全部不許可。
   - なので Claude は Yahoo! のページを開かない。読みとり方は、本人が保存して送った検索結果ページを見本にして作る。
   - 読むのは Supabase の Edge Function **route-yahoo**（2026-11-10 本人の OK で設置。コードは route/supabase/functions/route-yahoo/）。kotetsuworks.com からだけ受け付ける・1日60回まで・同じ検索は30分覚える。/search/result/ だけ読む。
   - ページ内の __NEXT_DATA__（naviSearchParam.featureInfoList）から、発着時刻・所要時間・運賃・乗りかえ回数・各駅の発着と路線を取る（parse.js）。
   - アプリは調べた結果を端末に覚え（S.auto）、同じ区間の時間も覚える（S.routes）。自分で直した時間は自動の結果より優先。
   - ページ内の注意書き：JR の時刻は交通新聞社のデータで「無断転載・複写・加工の禁止」。本人は「LINEヤフーの許可に含まれている」と判断（2026-11-10）。
2. 読めなかったとき・止められたときは「Yahoo!乗換案内で開く」ボタン（開くだけ）と、覚えた時間・自分で直した時間で動く。
3. 予備の候補（2026-11-10 確認）：NAVITIME（RapidAPI）無料プラン 月500回・0円・平均所要時間（時刻表ではない）・バスなし。駅すぱあと買い切り 5,000回 5,500円・ダイヤ探索なし。Google は日本の電車に対応と確認できず、本人の記憶でも出なかったので使わない。

## 定期・急ぎ・いつもの行き方（2026-11-10 本人の話から）
- 本人は JR 須磨〜南草津の定期を持つ。設定の「定期（JR）の区間」に入れると、JR西日本の東海道線・山陽線（本線）でその2駅の間の運賃は0円として数え、いちばん払うお金が少ない案を選ぶ（同じなら遅く出られる案）。区間の判定は stations.json の経度（m）で行う（和田岬の支線はのぞく）。
- route-yahoo は「早い順」と「安い順」の2回を読み、最大6案と区間ごとの運賃（edgeGroup）を返す。1日の上限は120回（検索60回ぶん）。
- 予定ごとに「急ぎ」を付けると、お金より速さを優先（到着指定なら一番遅く出られる案）。文字から入れるときは行の最後に「急ぎ」。
- 予定ごとに「できるだけ早く着く」：前の予定が終わったら（出発指定で）向かい、定期を考えて安い案の中で早く着くものを選ぶ。文字から入れるときは行の最後に「早め」。
- いつもの行き方（場所ごと）：行き＝どの駅でおりて何で何分、帰り＝どの駅まで何で何分。例：立命館大学 BKC は 南草津からシャトルバス（行き25分・帰り20分）、京都アクアアリーナは 行き 西大路から歩き30分（OpenStreetMap の位置で直線約2kmからの目安）、帰り 西京極まで歩き10分（本人）。
- 帰りがずれたとき用に、移動ごとに「1本前」（今の電車の到着の1分前までに着く案で調べ直す）「1本あと」「いまから出る（今日だけ）」「もとにもどす」。
- 授業の時間（時限）を設定でき、「1-5限 授業 @立命館大学 BKC」のように書ける。初めの値は仮（立命館 BKC 想定・未確認）。
- リンクで予定を入れる：短いリンク kotetsuworks.com/route/#i=コード（本人の希望でこちらがふつう）。Claude が Supabase の表 idounavi_share（設定 030）に予定を入れ、アプリは idounavi_take(コード) で読む。7日で消える。表は外から直接さわれない。長いリンク #import=（JSON を base64url）も使える。開くと確認してから、その日の予定を入れかえ、行き方・定期・家も入れる。

## 見た目（2026-11-10 本人と決定）
- 雰囲気は「路線図」：1日を1本の路線に見立て、予定が駅（太い丸）、移動が線。線は乗る路線の色に近い色（JR 神戸・京都線は青、阪急はえんじ、御堂筋線は赤など。公式の色そのものではない）。歩き・バスは点線、すき間は細い灰色の線。
- いつも白地。文字は太めのゴシック（Noto Sans JP）、時刻は桁のそろう数字（Roboto Condensed）。
- いちばん上に「つぎの行動」（黒いカード）：家を出る・電車に乗る・降りる時刻と、その次の3つ。きょうは「あと〇分」。1本前・1本あとのボタン。
- 下にタブ：今日・カレンダー・大会（まだ決めていない数を赤丸）・設定。予定を入れるのは右下の「＋」。
- 移動のボタンは「1本前・1本あと・いまから出る」だけ見せ、ほか（Yahoo!・行き方・直す）は「…」の中。

## カレンダー（2026-11-10 本人の希望）
- 「カレンダー」タブ：月の表（日ごとに「大学」「部活」「大会」などの短い名札）と、これからの予定（今日から予定のある日を30日ぶん）。日をタップするとその日の表へ。
- 同じ場所で続く予定（あいだ60分まで）は1つにまとめる。大学の授業は「大学 9:00〜18:15」のように時間だけ（教科ごとには出さない）。大会は赤。

## データ
- 予定・場所・覚えた移動時間はその端末（localStorage「idounavi-v1」）に保存。
- KOTETSU WORKS にログインしていると、アカウント（kw_app_data・app=route）にも保存し、どの端末でも同じにする（route/cloud.js。2026-11-10 本人の希望）。Yahoo! の検索結果（auto）は端末ごと。
- アカウントと端末の両方で変わっていたら、「前にそろえた時」とくらべて3つでまぜる（どちらかを選ばせない）。予定は日ごと・行き方は場所ごと・大会は大会ごと（出る／出ないは端末で押したものを残す）。同じところを両方が変えたら端末を優先。キーの並びをそろえてくらべる。（2026-11-10、選ばせる作りで Claude が入れた大会の候補が消えたため直した）
- KOTETSU WORKS の入口では「自分だけのアプリ」（kw_app_kind='private'）。本人（kotetsu）に渡し済み。管理者の「アプリを渡す」からほかの人にも渡せる。設定 031。
